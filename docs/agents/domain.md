# Domain Docs

本仓库采用 single-context。以下规则约定工程类 skill 如何读取领域文档。

## 探索前读取

- 根目录 `CONTEXT.md`：读取领域术语与上下文。
- `docs/adr/`：读取与当前任务相关的架构决策。

如果文档不存在，静默继续，不报告缺失，也不建议预先创建空文档。
由 `/domain-modeling` 在术语或决策实际明确时按需创建。

## 文件布局

- `CONTEXT.md`：仓库级领域上下文。
- `docs/adr/`：仓库级架构决策记录。

若将来存在根目录 `CONTEXT-MAP.md`，优先按其中的索引读取相关上下文，
并检查对应 `src/<context>/docs/adr/` 中的决策。

## 使用术语表中的名称

工单标题、重构建议、假设和测试名称涉及领域概念时，
使用 `CONTEXT.md` 定义的术语，避免换用术语表明确排除的同义词。

需要的概念不在术语表中时，先判断是否引入了不必要的新名称；
若确有缺口，记录为后续 `/domain-modeling` 的输入。

## 显式说明 ADR 冲突

建议或实现若与已有 ADR 冲突，指出对应 ADR、冲突点以及重新讨论的理由，
不得默默覆盖已有决策。
