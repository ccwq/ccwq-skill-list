# 校准案例

以下是创建时材料的摘要，仅用于标题决策。不要将其当成软件的当前事实；运行时使用用户本次提供的材料。示例标题用于说明写法，未获用户逐条认可。

## Clypra：从教程主线重选入口

材料：介绍开源、跨平台的视频编辑器，以及首次导入、裁剪、调音量、导出和外部验收；作者未安装实测。

- 可以从“第一条导出路线”转为“发现开源剪辑工具”，正文对此有支撑。
- 可以写“开源剪辑，多了一个选择”作为隐去名称的入口，另给“Clypra：开源视频剪辑新选择”这类明确对象版。
- 裁剪和导出教程不证明软件轻量、极速、稳定、无水印实测通过或可以替代商业剪辑器。
- “不想再用臃肿软件？”会暗示本工具更轻量，需要材料支撑这一比较；“试过才知道”需要实际使用记录。

## PhotoCraft：功能入口与替代结论分开

材料：图像编辑、PSD 图层、CLI、MCP 等文档声明；early alpha，作者未安装运行，强调格式需逐文件验收。

- 可以突出“让 Agent 操作图层”作为差异化卖点，并给出明确 PhotoCraft 的版本。
- “给 Agent 一套修图工具”可作为用途切入；具体标题仍要与本次材料中的调用能力一致。
- 支持 PSD 不等于完全兼容 Photoshop；具备 MCP 不等于内置 AI 生图或具有审美判断。
- “Photoshop 被替代了？”的问号不能代替替代证据。可以讲新选择，避免宣告成熟替代或全面超越。

## Matt Pocock 三技能：交付价值与自动化边界

材料：pr 写可审查的 PR 正文；implement-spec 按依赖与工单推进实现；retro 提出环境改进候选。用户触发、权限、执行环境和真实证据均有要求；文章未运行技能。

- 可以从技能名称转向“AI 写完代码之后，还缺什么”这一读者问题，同时提供明确写出 Matt Pocock 或三个技能名称的版本。
- 可以概括实现、交付、复盘的分工，不能把 pr 改写成自动审查或自动合并，把 retro 改写成自动改配置。
- “让错误不再发生”“装上就能放心合并”等保证超出材料。
- 全自动开发、已经验证的效率提升、发布版本号均需对应材料支持。

## 非技术内容与稀疏输入

- 生活教程：材料只讲苹果储存方法时，从具体问题与条件提炼价值，不添加营养疗效或品牌背景。
- 事件评论：以已提供的事实、争议和作者主张拟题，不把推断写成人物动机或已定案结论。
- 只有“家庭收纳”几个字：先按普通家庭读者给通用初稿，并用一句注明假设；不添加用户做过实验或已经节省多少空间的经历。
- 只有失效链接：说明未读到正文，请补充材料；不从 URL 猜测整篇文章。

## 交付复核

复核标题的每个数字、体验措辞、比较词和功能动词能否回到输入材料。复核六条是否实质不同、是否含明确对象版、是否只首推一次；输出结构、标题长度与理由要求按 SKILL.md 的“标题长度”和“输出与迭代”执行。将点击吸引力视为编辑取舍，不声称实际转化已经提升。
