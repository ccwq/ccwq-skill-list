# gemin-mirror

在 Gemini 或兼容镜像站上检查账号、切换账号或删除会话。

操作记录包含目标页面、唯一活动账号和删除前后的会话计数。删除结果必须经过刷新复核。

Skill 只处理用户明确授权的数据。它复用已有 CDP 标签页，不启动新浏览器。

## 使用前提

- 已登录的目标镜像站标签页，可通过 CDP 接入（默认端口 `9696`）。
- 已确认本次授权范围：是做只读探针，还是允许删除。

## 三种操作分支

| 分支 | 做什么 | 是否改动数据 |
|------|--------|--------------|
| 探针 | 读取页面、登录状态、账号证据与会话计数 | 否 |
| 当前账号删除 | 以唯一活动账号为目标，优先使用 API 入口 | 是 |
| 多账号删除 | 从默认适配器发现候选，逐个切换、核验、删除 | 是 |

多账号分支必须先确认使用默认适配器。

## 删除前的证据链

删除操作开始前，以下条件必须同时成立：

1. 页面 URL 位于允许的 origin，且登录状态有效。
2. `--expected-account` 与页面上唯一的活动账号证据完全匹配。
3. 已记录删除前的原生会话计数。
4. 多账号分支额外要求：目标 dashboard 卡片唯一选中、唯一活动邮箱、原生列表重新加载。

任一账号的证据不唯一时，工具必须停止该批操作并报告原因。

## 两个删除入口

- **API 入口**：`scripts/delete-sessions-via-api.mjs`。先捕获同源请求模板与运行时参数，再删除会话。限流或服务端失败时，工具执行有限重试。
- **DOM 入口**：`scripts/delete-current-account-sessions.mjs`。按实时元素位置逐条删除。只有用户明确选择回退时，才可以使用。

多账号遍历由 `scripts/delete-candidate-accounts.mjs` 完成，必须带 `--confirm-delete-all`。

API 入口使用 `--dry-run` 时，执行以下检查：

- 核验账号。
- 捕获请求模板。
- 统计候选会话。

此模式不发送删除请求。它仍会操作浏览器导航，并写入审计日志。

## 审计

审计记录时间、runner、账号短哈希、动作、before/after、重试次数、错误和 URL，写入本地 JSONL（默认在系统临时目录）。

运行时认证参数只在内存中使用。完整账号 ID、会话 ID、Cookie 与会话正文不进入审计。
