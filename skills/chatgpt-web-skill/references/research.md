# 研究与证据验收

用于 ChatGPT Web 的信息调查、方案比较和来源核验。普通图片任务不加载。本参考定义工作方法，不声称已验证当前页面的控件、搜索入口或完成状态。

## 1. 固定问题

从用户请求提取目标、硬约束、已核实事实、未确认事项、排除项与交付要求；版本、时间、地区只有影响结论时才补充。用户已说明的约束直接沿用，技术事实通过调查解决，只追问会改变路线且无法自行确定的取舍。简单问题不强制填写表单或建立报告目录。

发送的简报区分三类信息：

- **现场测量**：注明样本与条件，不从单个样本推出整体上限。
- **源码/文档结论**：注明版本与来源，不把产品宣传等同实现保证。
- **待验证推断**：作为问题提供，不写成已知事实或要求外部模型认同。

只发送必要的脱敏技术条件，不发送运行日志、凭据、账户信息或私有 URL。请求一手来源、反例与适用边界；优先提出足以否决候选的具体事实，避免先堆积大量泛泛比较。

## 2. 选择已获授权的模式

普通对话、Search、Deep Research 分别授权。按主文档的授权与完整发送规则执行；确认当前模式和本次完整用户消息后再等待结果。页面入口或选择器变化时现场发现，不将本参考视为固定 UI 契约。

Search 不可用不等于 Deep Research 获批；缺少搜索证据时只能标为普通模型分析。用户已授权所需模式时不反复询问同一授权。真实页面测试另需明确目标与测试内容，不因改过 skill 或本地测试通过而默认获批。

## 3. 分开记录四项证据

四项是独立检查，不是彼此替代的等级；每项使用“已确认 / 未确认 / 不适用”并附最短证据，不要求重复截图。

| 检查 | 足够的证据 | 不能代替它的信号 |
| --- | --- | --- |
| 消息完整送达 | 关联本次新增用户消息，完整正文、关键约束、末尾均通过 | 工具成功、首句或 marker 出现、composer 清空 |
| 回答生成完成 | 本次回答已有完整结论，并出现稳定终态控件；结合停止/生成中信号消失，无认证或错误中断 | 后台命令退出、部分段落出现、单独没有停止按钮 |
| 实际发生搜索 | 本次回答关联的可见搜索步骤或检索记录；区分“已开始”和“已结束” | 模型自称搜过、正文含链接、官方域名出现 |
| 来源支持结论 | 已实际读取关键来源，版本/范围匹配且原文支持具体结论，保留反例和限制 | 有引用编号、有链接、搜索摘要或域名可信 |

完成控件如复制/重新生成是现场线索，不是永恒选择器；若当前 UI 不提供足够组合证据，报告“生成完成未确认”。生成中的内容可汇报为进度，不发布为最终结论。确认检索开始也不表示引用内容已核验。

本 skill 只操作 ChatGPT Web。若关键来源需要外部浏览才能核验，将链接和待核验命题交给当前任务中另行可用且获授权的读取方式；否则标为“来源未核验”。让外部模型再次保证正确，不等于读取了来源。

## 4. 核验会改变决策的事实

先核验能否决候选的关键事实，再检查其余支撑结论。优先固定版本的官方文档、源码或原始研究；记录已读内容实际支持什么，而不是只复述回答中的链接。

例如，若目标要求保留全部原始字段，候选工具的 README 明示丢弃字段即可否决其“无损替代”资格；不必先复述所有搜索结果。该例只是判断方法，不是对某个产品的事实结论。

汇总前对照原简报检查目标漂移：内容完整性、读取兼容性和保留期是不同约束。“完整”不能自动扩成“永久保留全部历史”。建议改变目标时将其列为取舍，等待用户决定，而不是悄悄改需求。

结论使用明确状态：

- **不可行**：证据证明在指定条件下违反硬约束。
- **不推荐**：可行，但成本或风险不符合当前取舍。
- **未验证**：证据不足；不是不可行。

新证据否定旧判断时，同步修正任务已有的地图、决策记录或方案，注明原因与证据；没有这些文件就不为形式新增一套。不能只在聊天中改口，留下仍被使用的错误结论。

## 5. 交付与停止

按需简洁交付：结论及适用范围、关键来源与实际核验状态、未确认事项、四项证据状态。只对影响决策的断言追溯来源，不要求每个普通句子填证据表。

回答完成但来源未核验时，可以交付“模型建议，关键来源待核验”，不能报告“研究已验证完成”。预算耗尽、平台阻断或证据持续不足时，报告已确认到哪一步及阻塞原因，不自动追加研究轮次或扩大权限。

只把实际使用并验证的跨任务方法送入经验整理；不把本次正文、页面细节或本机排障记录写成通用规则。
