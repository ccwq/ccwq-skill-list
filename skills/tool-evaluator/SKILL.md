# 工具调查、比较、筛选与决策分析

用 **Gate-first** 流程将用户约束转换为可追溯的工具决策：先淘汰不合格候选，再根据证据和场景权重比较通过者。默认只做资料调查；安装、运行、修改配置、注册账号和 POC 均需要用户明确授权。

## 1. 定锚任务与约束

读取 [决策基线](references/decision-baseline.md)，判断本次是「指定候选比较」还是「探索筛选」，并提取核心目标、硬性需求、偏好、环境、预算、隐私与长期维护要求。仅在用户偏好会改变结论时提问。

**完成条件：** 已得到任务模式、候选边界，以及区分「必须」「偏好」「未知」的需求清单。

## 2. Gate-first 候选处理

依据 [决策基线](references/decision-baseline.md) 建立通用、类型专项和动态 Gate。指定候选时保持用户给定范围；探索筛选时覆盖主要技术路线，并在新增候选不再带来明显信息增益时停止。

**完成条件：** 每个候选都有「硬淘汰／严重扣分／进入评分」状态和可追溯理由；硬淘汰项不参与总排名。

## 3. 由浅入深地取证

读取 [调查方法](references/research-method.md)，先对通过 Gate 的候选快速初筛，再只对 Top N 深挖。记录来源、取证日期、证据等级和冲突；项目健康度必须使用趋势与上下文解释，而不是孤立指标。

**完成条件：** 每项会影响结论的主张都有 L1、L2 或 L3 标记；冲突、缺口和未经实测的能力均已显式列出。

## 4. 按场景评价与稳健性检查

读取 [评价框架](references/evaluation-framework.md)，为候选选择通用维度、原始分、动态权重和结论置信度。仅在工具类别适用时加载 [专项指标](references/category-rubrics.md)。检查关键权重变化是否会翻转排名，避免将微小分差写成确定胜负。

**完成条件：** 评分依据、权重、置信度、未知项和敏感性结论彼此独立且可复核。

## 5. 交付决策并管控 POC

读取 [报告与 POC](references/report-and-poc.md)，按固定结构输出首选、次选、条件性首选和不推荐项，并明确改变推荐的条件。只有关键未知项足以影响决策时才提出 POC；未收到明确授权时，仅提供可执行的 POC 方案。

**完成条件：** 报告能直接支持选择，区分事实、推断、声明和实测，并附带已确认风险、关键未知项与下一步。
