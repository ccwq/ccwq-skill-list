# 提交计划 Grilling

进入本分支后，逐问审查当前提交计划，直到关键决策由用户确认；本技能自足，不依赖外部 grilling skill。参数与组合速查见[根 README](../../../README.md#git-up)。

## 准备

沿用会话中记录的规划深度；只有用户显式选择 deep 才切换深度。无当前计划时，先按当前深度完成规划并展示完整 YAML，再开始提问。发现计划与工作区不一致时，先核对必要的 git 状态、代码或 diff，再提出依赖用户选择的问题。

## 逐轮审查

1. 检查当前计划的分组、范围、依赖和风险。优先审查会影响后续决策的项：业务完整性、文件归属与排除项、提交顺序、回滚边界或尚未验证的假设。
2. 每轮仅提出当前最相关的 1–3 个问题。`AskUserQuestion` 可用时使用该工具，给出推荐选项、推荐理由与取舍，并允许用户补充；不可用时以文字选项提问。
3. 发问后等待用户回答，不自答、不把推荐项当作已确认。根据实际回答继续调查或调整计划，再决定下一轮问题。
4. 用户回答导致计划变化时，展示更新后的完整 YAML，并同步已有计划工件。关键决策确认后，总结已确认项及未解决风险，停止在计划审查阶段。

轻量深度始终保持整文件归组：只讨论文件级分组、范围与顺序，不展开同文件语义拆分、不生成补丁。deep 可审查语义组及其依赖；计划采用 `files` 并不改变已记录深度。

## 非提交边界

此分支只做只读核验、提问和必要的计划工件更新，不修改业务文件、HEAD 或 index，不提交、不 push、不委派提交。讨论达成共识也不构成提交授权；用户需另行发起明确的提交动作。与其他主动作冲突时解释并停止，不以“先讨论再提交”自动串联执行。
