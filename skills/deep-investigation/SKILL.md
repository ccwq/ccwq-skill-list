# Deep Investigation（深度调查）

这是一个 user-invoked Skill。以 `$deep-investigation <调查话题>` 显式调用；不声明或依赖 slash command 别名。

1. 收到话题后，先完整读取 [protocol.md](references/protocol.md)。话题缺失时，只询问调查对象与范围。
2. 先校正可证伪的错误前提，界定时间范围、地域与关键主体；近期或持续演变事件主动联网，优先取得原始材料。
3. 建立**证据账本**：每项关键结论记录来源、原始程度、独立性、时间、事实等级和仍存缺口。把事实、当事方主张、合理推断与未知分开写。
4. 环境支持子智能体时，按协议将事实历史、主体关系和反证来源分给 2 至 3 个独立分支；先独立取证，后交叉核验。不能创建子智能体时，按这三种视角串行完成，并在综合前做反证检查。
5. 沿“当前事件 → 直接起因 → 有解释力的历史根源 → 分支演化 → 主体关系与利益 → 证据冲突”推进。相关、受益、合作和接触分别只说明其自身能证明的关系。
6. 按协议的报告结构交付高密度调查结论；只保留有材料支撑的章节，证据不足处明确标记，来源按对结论的重要性排序。

## 质量门

- 每个核心判断都有可追溯证据或明确的不确定性标记。
- 至少检验一个合理的竞争解释，并说明何种新证据能推翻当前判断。
- 多源转载不算独立验证；不得用立场、标题或动机猜测替代证据。

完成条件：核心结论、证据账本、关键时间线、关系判断、竞争解释与未解问题彼此一致；无法确认的内容保留为未知，而非补全为结论。
