# Bash 补全：先分能力，再验行为

## 1. 明确目标与体验

确认目标环境、**安装执行身份**、**交互配置使用者**及作用范围。在 WSL、多账号或需提权时先读 [环境与交接](references/environment-handoff.md)：现场发现环境与账号，不能从提权后的 HOME 推断配置对象。未指定远程目标时先问。独立选择优先用宿主 GUI 问答。

分别标记普通 Tab、模糊选择、输入时建议、语法高亮、历史搜索、目录跳转。输入后无提示不等于 Tab 故障。按 [能力模型](references/completion-model.md) 给出可观察的期望。

**完成标准：** 目标、账号、需要和不需要的能力均明确。Bash 以外的 shell 说明首版边界，不替用户更换默认 shell。

## 2. 只读基线

先读项目规则。远程维护仓库读 [仓库适配](references/project-adapter.md)，其他项目使用自己的连接入口。

运行 [静态探针](scripts/probe-bash.sh) 获取当前进程模式、TTY、locale 环境值、工具路径和启动文件存在性。探针用 POSIX sh，可通过 stdin 交给 `/bin/sh -s`；不执行找到的工具、不 source 配置、不输出完整环境或配置正文。

区分执行器现场、用户真实会话和未测信息。探针缺少环境变量不能证明真实 SSH 会话也缺少。版本及语法检查按需单独执行并保存真实退出码。

**完成标准：** 记录执行器已观测的 shell/模式、TTY、路径和配置接入点；目标用户真实交互启动模式另行核实。未验证假设明确列出，不将安装存在判为功能可用。

## 3. 分支处理

- **已有故障：** 读 [分层验证](references/verification.md)，构造匹配用户操作的最小复现，一次改变一个因素。先检查期望是否属于组件能力，再检查绑定和委派。
- **安装修改：** 读 [安装回滚](references/installation-rollback.md)，执行“满足复用／冲突先审／缺失补齐”的状态判断，未知先查证。按接口和配套集成文件选包，优先目标版本的官方兼容层；bat/eza/rg 为可选配套。
- **ble.sh：** 使用 PTY 与无 `-c` 的交互 Bash 分支；函数存在不等于编辑器已 attach。版本限制查对应说明或源码。
- **容器安装验证：** 用户授权干净环境回归时读 [隔离安装回归](references/container-lab.md)，覆盖首次登录、幂等、账号隔离与回滚；容器不替代完整虚拟机验收。
- **启动顺序/PATH：** 分别追踪 login/non-login、interactive/non-interactive 及既有管理器。nvm/Volta 修补不是默认步骤。

**完成标准：** 每个结论有对照证据；未复现就写“未复现”，请求最少补证。两次同类引号或环境错误后先修测试构造，不继续堆探针。

## 4. 变更关口

说明目标、文件/包、作用范围、来源校验、备份、回滚和验收项目，获明确确认再写入。全局二进制可用与所有用户自动启用交互配置分别确认。

采用独立配置与带标记的幂等接入块；先备份、验证语法，再分阶段应用。仅 source 成功且加载状态符合预期时 attach。保留旧会话作为救援入口，用新会话验证。

**完成标准：** 授权范围与实际 diff 一致；异常即停下报告，不扩大为顺手修其他工具。

## 5. 行为验收与交付

按 [验证矩阵](references/verification.md) 分别验候选、UI、快捷键、建议、高亮、跳转。获授权后可用 [实验性 PTY 验证器](scripts/verify-pty.py)：默认干净 Bash，真实配置必须显式启用；它在已选定的 Unix 环境内运行，不负责连接或提权。不要求固定候选数量。验证重复加载与非交互回归，不能观测的项目标“待验”。

输出 `能力 | 期望 | 实测/用户确认 | 证据 | 状态`，附变更、回滚摘要。临时输出集中到一个目录，按授权清理，遵循批量删除限制。

**完成标准：** 需求逐项通过或明确未决；旧案例不升级为通用事实。编写技能和离线评审不授权连接生产主机。
