# 能力模型

| 能力 | 触发与判据 | 常见提供者 |
|---|---|---|
| 命令名补全 | 如 `gi` 后 Tab，匹配 PATH 中命令；不同于 `git ` 后补参数 | Bash/Readline |
| 参数/子命令补全 | `git ch` 后 Tab，候选符合 git 语义 | programmable completion、bash-completion |
| 模糊路径选择 | fzf 常见默认是输入 `**` 后 Tab；触发符以实际配置为准 | fzf shell integration |
| 历史/文件/目录搜索 | Ctrl-R / Ctrl-T / Alt-C 等，检查实际 keymap 和配置 | fzf 或编辑器集成 |
| 输入时自动建议 | 不按 Tab 也出现建议，明确接受/取消按键 | ble.sh 等编辑器 |
| 实时语法高亮 | 未执行时命令、字符串等按规则变色 | ble.sh |
| 智能跳转 | 用已登记目录的关键字跳转；默认 z/zi 与接管 cd 是不同选择 | zoxide |

## 委派与懒加载

bash-completion 可按需加载命令定义；fzf 可包装并保存已有 completer。看到 `_fzf_path_completion` 不能推断“只剩文件路径”，缺少名为 `_git` 的函数也不能推断 git 补全缺失，实际实现可能使用 wrapper。

普通 Tab 不自动等于 fzf UI；缺少 `_fzf_complete_git` 不等于 git 无法使用通用模糊路径选择。默认 `**` 触发通常筛路径，不保证筛 git 子命令。想要所有普通 Tab 候选都进菜单，需要单独选定编辑器/集成并验证。

先通过干净对照定位差异，在目标插件组合稳定复现并证实与懒加载/委派有关后，才考虑提前加载某命令定义。干净环境没有故障并不否定组合冲突。优先使用目标版本支持的加载 API；保留原 completer、作用域隔离 `COMP_*`、验证加载成功后才设置标记。不要默认对所有命令预热，不凭候选条数推导内部根因。

## 案例的证据边界

一个历史环境中，提前加载 git 定义后 `git ch` 能返回语义正确的子命令，用户确认普通候选可用。这证明该环境的修补有用，不证明任意 fzf/bash-completion 组合都会冲突，也不证明默认 Tab 会弹 fzf 菜单。另一环境可能不需要此补丁；先复现再决定。

“输入时没有提示”先问是否指自动建议，而不是连续修改 Tab 处理器。颜色确认只证明颜色，不证明自动建议或键绑定也通过。
