# BusyBox / musl / 路由系统分支

适用于 Alpine、OpenWrt 或其他精简系统；包名和路径由现场发现，不把某发行版经验当统一安装器。已执行范围与限制见 [跨发行版验证记录](../evals/musl-validation.md)。

## 基线与包来源

1. 记录实际 release/架构/libc loader、包管理器及版本匹配的签名仓库。OpenWrt并非所有版本都用opkg；Alpine与OpenWrt即使都用apk也不能混用仓库或包。
2. 保留默认ash与/bin/sh；Bash作为显式调用的附加shell。安装身份、普通账号及root测试路径分开。
3. 分别检查运行依赖与测试依赖。BusyBox是否带某applet由编译选项决定；不能从“有BusyBox”推断tty、od、ps、stty、timeout全都可用。根据实际错误补目标仓库的最小组件。
4. 包缺失时评估官方上游发布物的架构、libc、摘要及运行依赖。先非root验证版本/接口，再纳入配置。禁止以跨发行版包替代缺项。跳过归档链接时记录功能损失，不宣称整个安装树完整。

**完成标准：** 来源、签名/摘要信任边界、实际依赖与文件路径可追溯；不会为安装组件顺手升级系统或启动路由服务。

## 用户目录和启动链

- 新建账号可能没有.bashrc/.profile；写入.bashrc不证明bash -il会读取。核实优先级和现有入口，必要时新增Bash专用.bash_profile桥接；已有profile不能被新入口静默遮蔽。新增入口单独备份/记录/回滚。
- HOME可能带setgid，新目录继承为2700。只对本次新建私有状态目录显式chmod0700，保留HOME与既有目录权限；已有不安全状态仍拒绝。
- 普通账号可能无法写/tmp；为测试设置目标账号私有TMPDIR，不修改系统/tmp权限来迎合测试。
- ble的缓存目录与运行目录是不同前提。没有登录管理器时，XDG_RUNTIME_DIR可能缺失；按版本源码检查回退。获授权后可在本机/容器的易失运行目录中为UID预置0700属主目录，保留已有XDG选择，不让共享ble安装树对所有用户可写。
- /run目录的生命周期由系统管理；容器中的目录留存不证明重启后真实系统会自动创建。正式设备需接入合适的登录/启动生命周期后另验。
- 设置USER/HOME/SHELL等需匹配实际账号；某系统profile会按USER重新推导HOME。locale是否可用单独验证，不靠统一字符串证明Unicode显示正确。

## 易失目录与冷启动验收

当安装依赖/run等易失状态时，单独记录目录的重建责任（现有登录管理器、系统启动机制或授权的专用入口）。仅手工mkdir能证明当前会话可用，不能证明开机可用。

1. 先在可丢弃副本核验重建机制；真实设备重启另取维护窗口授权。保护正在手测的账号和容器。
2. 明确实验条件：普通容器stop/start可能保留可写层中的/run，不能冒充清空易失目录的开机测试；使用独立副本及明确的易失挂载/新实例条件。
3. 在未预热缓存、未注入测试XDG目录的新登录中检查实际UID/HOME、runtime属主/0700、加载/attach、快捷键与非交互基线。
4. 返回 `verified / failed / not_tested` 与实验条件。失败时先恢复登录通路，不放宽共享目录权限；未实际执行就保留not_tested。

**完成标准：** 当前会话与冷启动证据分开；不能用上一轮容器通过结果替代真实设备重启验收。

## 验证与回滚

先验证干净Bash，再逐组件启用、真实XDG首次登录、login/non-login、ash对照。系统profile可能原本输出banner；比较配置启用与恢复基线后的stdout/stderr/exit，验“无新增行为”，不为全绿去删系统banner。

原.bashrc不存在时，正确回滚是恢复不存在，不创建空文件，也不在测试中强行read_bytes。额外登录入口、缓存/runtime目录与包安装均须另列清单；配置夹具回滚只涵盖自己的manifest范围。

root路径只在显式授权的可丢弃容器单独验证。外层核实容器标签/ID，测试前检查原文件、记录内容/权限，漂移时停止，测试后还原。保留通用配置夹具的非root保护，不因路由设备常用root而去掉安全门槛。

**完成标准：** 普通账号与root证据分开，未配置账号为负对照；默认ash与系统profile保持原样，回滚范围逐项说明。容器只代表用户空间兼容，不证明设备内核、无线、procd、闪存、SSH/PAM或性能。
