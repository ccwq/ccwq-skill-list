# 分层验证

## 执行环境矩阵

| 环境 | 能说明什么 | 不能替代什么 |
|---|---|---|
| POSIX sh 静态探针 | 当前进程模式、路径、TTY、导出变量 | 目标用户 Bash 函数/未导出变量 |
| `bash -c` | 非交互执行路径 | 用户交互启动配置 |
| `bash -lc` | 非交互 login 路径 | 任意 SSH 命令的真实启动方式 |
| `bash -ic` / `bash -ilc` | 相应交互标志与配置加载 | 控制 PTY、编辑循环；存在 `BASH_EXECUTION_STRING` |
| 有控制 PTY 的 `bash -il`，不带 `-c` | 真实编辑、建议、按键、attach | 人对手感和视觉效果的最终判断 |

启动用户配置是主动执行代码，可能写缓存/历史或调用其他程序；说明影响并获得授权。先保留救援会话。PTY 测试在已选定环境内启动无 `-c` 的 Bash，通过 PTY 输入命令与按键。设置尺寸、TERM、超时并确保关闭自己创建的会话。未实际跑过就写“未测”，不写“无法自动测试”。

## 可选 PTY 验证器

[verify-pty.py](../scripts/verify-pty.py) 是**实验性主动验证器**，与静态探针分开；已知真实组合兼容性限制见 [验证记录](../evals/validation.md)。测试器超时只代表本次协议未完成，不能单独证明用户补全故障；保留失败并对照实际会话，避免为了全绿改用户配置。先运行 `python3 verify-pty.py --help` 查看接口；在已选定环境内以目标配置账号运行，不用 sudo。默认干净 Bash和临时HOME；`--user-config` 才加载真实用户启动文件。Bash路径、测试项和超时均由调用参数指定，不内置环境连接逻辑。

干净模式隔离HOME/XDG与历史；真实配置模式保留目标HOME以测试实际启动链，仅将测试历史、跳转库、XDG测试数据及cwd隔离。若目标仅从XDG配置目录加载插件，隔离可能让该配置未加载，结果需注明测试模式差异，不能直接判定真实会话未安装。启动配置仍可能重设变量、写绝对路径、联网、启动进程；隔离不等于沙箱，也不能宣称对用户环境零副作用。

每项独立会话：确认唯一就绪响应 → 操作 → 检查目标候选/界面证据 → 取消 → 确认唯一恢复响应。执行确认之后还需等待新的唯一提示符，作为已实测组合的同步信号再发送编辑快捷键（不是所有编辑器的通用 idle API）；Tab 后先观察补全路径，再发送 Enter，并以执行后的随机内容验证，不能把路径回显当成功。终端查询需处理分片；固定等待只作退让，不作验收标准。

**真实启动对照：** 隔离 XDG 会预建缓存目录，可能掩盖新账号首次登录缺陷。隔离测试通过后，在授权的测试账号中保留其实际 HOME/XDG 再验证首次启动；这一步允许正常缓存写入，不能宣称只读。容器夹具与运行方式见 [隔离安装回归](container-lab.md)。当前验证器用控制序列剥离而非完整屏幕渲染，CPR 使用固定位置回复；不证明 Unicode 宽度、光标布局或同一屏幕帧的视觉正确性。

输出为结构化状态、固定枚举的 `phase`（就绪/设置/候选/恢复/取消/状态检查）和最小证据，不默认保存真实终端全文。内存中会短暂接收启动输出；它可能含敏感内容，调试时仅输出脱敏阶段信息。结果区分 `pass` / `fail` / `unsupported` / `not_tested`，部分不支持不能报全绿。退出码 0=所选检查通过，1=存在失败，2=参数错误或部分不支持（结合 stderr/JSON 判别）。超时清理自身shell进程组和经session核验的前台进程组，回收shell；不能保证回收启动配置自行脱离session的进程。只删除本次临时目录。

临时目录创建失败返回 `fail / phase=setup / reason=temporary_directory_unavailable`，退出1，且不启动Bash；不输出异常中的真实路径。这是环境前提失败，不代表插件故障。检查目标账号可写空间，按需显式提供私有TMPDIR；不自动改变系统临时目录权限。此项只覆盖创建失败，不宣称所有清理/进程异常都已结构化。

从 skill 目录调用示例：

```bash
# 隔离验证基础接口，不加载真实配置
python3 scripts/verify-pty.py --tests readiness,tab --timeout 15
# 以下仅在目标账号已授权加载配置之后执行
python3 scripts/verify-pty.py --user-config --tests readiness,tab,fzf-history,fzf-files,fzf-dirs,ble --timeout 20
```

默认不会给干净环境安装或初始化插件，因此全项目检查可能返回 unsupported；不要为了追求全绿绕过显式授权。工具的 `tab` 测受控路径补全，不等于验证 git 子命令；fzf采用受控候选提供者，不证明用户自定义搜索命令。

Tab文件补全、git语义补全必须注明测了哪一种；fzf测试分别证明进入与取消后恢复，不能由bind表代替按键。ble测试只证明加载/attach/选项；建议出现与接受、视觉高亮和主观卡顿由额外测试或人工验收补齐。

## 保存退出码

先运行，再记录退出码，最后过滤输出。Bash 管道需要即时复制整个 `PIPESTATUS`；POSIX sh 用独立命令及临时输出文件。`pipefail` 不解决所有问题，`head` 提前退出可触发 SIGPIPE。`echo "$(cmd)"` 的成功不能代表 cmd 成功。

## 验证矩阵

1. **静态与语法**：配置存在性、目标 shell 语法、工具实际来源。新起探针不能读取父交互 shell 的未导出函数。
2. **语义候选**：在隔离作用域设置完整上下文，如 `COMP_WORDS=(git "")`、`COMP_CWORD=1`、`COMP_LINE="git "`、`COMP_POINT=4`。从已观察的注册项确认函数；调用后记录退出码及候选语义，不断言固定数量。loader 的 124 等返回值按对应协议解释，不一概当失败。probe 自定义函数/变量用完释放。
3. **真实 Tab**：区分命令名、子命令、参数、路径；记录是否按一次或两次 Tab。候选生成通过不代表 UI 通过。
4. **fzf**：分别试实际触发符（常见 `**`）及 Ctrl-R/T/Alt-C。Readline 检查 `bind -p`（函数）、`bind -s`（宏）、`bind -X`（shell命令），同时检查 emacs/vi keymap。ble.sh 使用其绑定层，查所装版本接口，不能凭空编 widget 名。
5. **ble.sh**：真实 PTY、无 `-c` 会话中检查版本、加载返回值、attach 状态及未执行输入的高亮/建议。历史版本可拒绝 `BASH_EXECUTION_STRING`。`3>&2` 保存 stderr 后的 `>&3` 仍可能显示诊断，不能概括为“错误全被吞”。
6. **跳转**：明确 z/zi 或 cd 接管；用用户同意的临时目录与隔离数据目录验证模糊跳转，避免污染真实跳转库。
7. **回归**：新旧会话、重复 source、PATH 和提示钩子是否重复、非交互 stdout/stderr 是否出现新增噪声；工具可找到不等于 pnpm/yarn 等代理命令可运行。

## 视觉与环境归因

UTF-8 编码正确不等于终端字体与字符显示宽度正确。`wc -m` 计字符，不能验证视觉列对齐。用户 `LANG=en_US.UTF-8` 本身不是异常，不为统一字面值强制改 locale。

eza 等 CLI 空输出时对照显式 `eza .`，控制 stdin 是 PTY、空输入还是路径列表，记录 cwd/版本/配置/TERM。stdin 行为和终端行为分开测，不能仅凭换 PTY 后正常就锁定根因。

## 本 skill 离线测试的范围

静态探针自测与情景评审只证明接口、边界和决策流程，不声称目标主机或 PTY 交互通过。不在离线测试中 source 实际用户配置。
