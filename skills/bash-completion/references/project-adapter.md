# 本仓库适配（通用 skill 的可选分支）

## 何时用

仅在项目规则声明用 `scripts/remote-host.mjs` 维护已登记主机时采用本页。复制 skill 到其他项目后，没有该入口就遵守目标项目规则，不猜测 SSH 地址或账号。

## 连接与范围

1. 先读实际 AGENTS.md 与相关主机配置，确认目标明确且已登记。只取必要字段，不输出整个含凭据的 env 文件。
2. 统一入口示例（HOST 是用户已确认的名字）：

   ```text
   node scripts/remote-host.mjs HOST --script .agents/skills/bash-completion/scripts/probe-bash.sh
   ```

   当前仓库 `--script` 由 `/bin/sh -s` 执行 stdin，不依赖脚本 shebang。附带探针采用 POSIX sh；Bash 主动测试需显式选 Bash 与正确启动模式。
3. Windows 调用优先传脚本路径而非层层引号嵌套；保留 node 退出码再格式化输出。连接层与远端命令失败分开报告，不自行扩大传输回退。
4. 安装、配置、升级、回滚等写操作先说明范围获确认。主机独立维护，一台主机的事实不自动应用于其他主机。

## 经验来源的使用方式

本 skill 从历史 tenc 实践提炼，原文有过度断言。当前操作以主文档和分支参考为准，不以老的阶段脚本为安装器；不依赖根 docs、备份树或记忆库才能使用。

可复用经验：执行器 sh 与目标 Bash 不同；懒加载与包装后的函数名不能证明候选是否正确；输入建议不同于 Tab；TTY、stdin、启动模式必须匹配；PATH 修补要追踪整个启动链。

暂不泛化：固定候选数量、历史测速、版本号、eza 空输出归因、fzf “永不懒加载”、ble.sh “只能人工测试”。

## 项目卫生

新 skill 的 Git 例外应逐级开放 `.agents/skills/`、本 skill 目录及内容；只改所需规则并验证，不提交任何未授权文件。测试输出用系统临时目录，使用明确的本次文件清单清理；不删除其他任务的 tmp 文件。原有脚本和文档保留不动。
