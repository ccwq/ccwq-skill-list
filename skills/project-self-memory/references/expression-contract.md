# 内置记忆表达契约（STE-zh）

本契约把适用于记忆正文的简化技术中文（STE-zh）表达原则固化为 project-self-memory 的内置规则，随 Skill 分发。它是中文改写原则，**不是 ASD-STE100 官方中文标准**；执行时不读取开发者机器上的全局 ste 安装，不联网，不调用外部模型。

分工边界：

- **宿主**：在调用写入入口前完成语义改写——保留可信结论、事实、适用条件与字面量，把候选正文压缩为紧凑单行。
- **CLI / 查看器**：只做确定性结构校验（`memory-store.mjs` 的 `contentContractErrors`）：非空、单行、无标题/列表/围栏、无 psm 结构标记。CLI 不判断事实真伪、主动语态、一句一事或语义一致性；这些由宿主负责。

## 改写原则（宿主职责）

一条记录围绕**一个可复用结论**。

1. **一句一事。** 一句只表达一个事实或一个动作；关联的前提、结论、例外可以用多个短句写在同一物理行。
2. **一词一义。** 同一概念在一条记录内只用同一个词；先定义后使用的项目专用词保持稳定写法。
3. **用具体动词。** 写「修改配置」，不写「对配置进行修改」；能写出具体动作时不用「处理」。
4. **主动语态、主语明确。** 写出谁做动作；主语省略后有两种读法时补出主语。
5. **条件前置。** 先写适用条件，再写动作或结论。例：「连接失败时，重试一次」。
6. **情态词固定。** 只用「必须」「不得」「可以」表达要求、禁止与允许。
7. **句长上限。** 步骤句不超过 30 字，描述句不超过 40 字；一个汉字计 1 字，一个英文单词、数字或代码标识符计 1 字，标点不计。宿主按混排原则人工检查，不把字符串长度当作语义句长的等价替代。
8. **保留不确定性。** 未经验证的推断保持「未确认」表述，不得在改写中升级为事实。

## 单行存储（确定性校验）

- 正文输入可以去除外围空白（含文本文件末尾的单个换行）；去除后不得含内部物理换行或 Unicode 行/段分隔符（U+2028/U+2029）。
- 正文不得以 Markdown 标题、列表标记或代码围栏开头；不得包含 psm 结构标记。
- 单行要求优先于 STE 的标题、编号步骤、竖排列表与段落模板。不为满足汇报模板而向正文加入「改动」「验证」或工作进度叙述。
- 不得用「简单去掉换行」冒充语义改写：改写必须保留原意，而不是把多段文本拼成一行。

## 字面量与证据（宿主职责）

- 命令、路径、代码标识符、错误串保持原文；不得压缩命令参数、不得翻译标识符。
- 行内代码与链接可以保留；不加与结论无关的装饰。
- 既有合法分类前缀（如 `[host_scope=tenc]`）保持原文及原有适用范围；不得把多个主机范围合并为未经证实的范围。
- 改写不得产生新事实：更好措辞不能创建原文没有的声明；可以改写为经证据支持的结论并引用稳定资料，但不得凭空创建引用。
- 某段多行代码无法在保留原意与字面量的同时满足单行要求时，**不保存该候选**：返回可定位原因并跳过，不原样回退保存。

## 授权边界

表达改写与写操作授权是两件事：

- 改写不增加宿主的保存权限。自动保存仍仅限全新、已验证、无冲突、不需要用户取舍的结论。
- 用户已授权具体修订时，可以自动改写这次修订的正文并暂存进 cache；落库仍须经 `-c` 确认。未获授权的修订仍不得暂存。
- 表达改写免二次确认，不等于写操作免授权。自动流程只暂存候选，不得直接写入记忆库；合并、删除、评分与状态变更也只作为候选暂存，落库一律经 `-c`。
- 不改写既有记录：新正文规范只在正文实际新增或变化时检查；评分、标签、分组、状态等元数据维护与 no-op 不要求重写旧正文。

## CLI 校验的错误输出

校验失败时命令退出 1，错误原因带 `PSM_CONTRACT` 标记并给出可定位原因；CLI 统一错误出口会再加 `PSM_ERROR:` 前缀，实际输出形如：

```text
PSM_ERROR: PSM_CONTRACT: 新正文不符合单行契约 — 新正文必须单行：去除首尾空白后不得含内部换行（含 CRLF 与 Unicode 行/段分隔符）
```

宿主匹配 `PSM_CONTRACT` 识别契约错误，根据原因修正内容后重试；CLI 不提供语义改写。查看器的正文编辑走同一校验（PATCH 返回 400 `CONTRACT`），磁盘内容不变。
