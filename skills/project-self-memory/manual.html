快速上手

只记结论，不记聊天流水。 新结论先进入暂存区。用户确认后，候选才进入记忆库。
  1. 确认入口。 在目标项目中，让 Agent 使用已安装的 project-self-memory。安装方法见根 README。已有用户级安装时，不必在每个项目重复安装。
  2. 读取记忆。 请求「检查本项目的 PSM，读取与当前任务相关的记忆」。缺库时确认初始化；库损坏时只诊断。
  3. 完成业务任务。 把记忆当线索，核验当前代码与环境。
  4. 暂存结论。 请求「把本次已验证的新结论先暂存，不入库」。检查暂存条数与候选编号。
  5. 审核入库。 请求「逐条展示暂存候选，由我决定写入、丢弃或暂缓」。写入后回读结果。

自然语言请求必须发给能加载此 Skill 的 Agent。自动行为还取决于配置与宿主接入，安装 Skill 不等于后台服务。

日常场景

以下为请求示例。编号与业务内容必须换成当前项目的真实内容。

读取与任务相关的记忆

使用 PSM，读取与本次部署任务相关的记忆。说明哪些结论仍需现场验证。

结果：Agent 读取相关记录。读取不表示结论仍然有效，也不产生评分。

把结论先攒起来

把本次任务中已验证、可复用的新结论暂存进 PSM。不要直接入库。报告候选编号。

结果：候选进入暂存区，跨会话保留。记忆库与评分账本不变。

审核已有候选

逐条展示 PSM 暂存候选。修改类先展示原文与新文，等我选择后再执行。

结果：Agent 进入候选审核。没有候选时直接结束，不制造问题。

盘点本次经验

用 PSM 盘点本次经验，检查重复与冲突。先讨论，不保存。

结果：Agent 逐问核对结论与适用范围。认可结论不等于授权写入。

修订一条已知记忆

检查 PSM 记录 0001。先核验现状，展示修订前后内容，等我确认再修改。

结果：先读后写。具体修改获得授权后，可以直接修订；不必先放入暂存区。

评价实际用过的记忆

评价本次实际采用的 PSM 记忆。区分有效、在适用范围内失效、无法归因。先给建议。

结果：只讨论有实际结果的记录。任务失败或场景不匹配，不自动等于负分。

打开查看器

为当前项目启动 PSM 统一 preview。不要部署运行时副本，也不要改项目数据。

结果：启动本机页面。可以浏览记忆与暂存候选；点击写操作才会提交变更。

本次不自动保存

本次任务继续读取 PSM，但关闭自动保存与自动评分。不要在收尾时暂存结论。

结果：任务级覆盖生效。关闭自动行为不删除已有记忆或候选。

显式 Skill 调用与全部参数只在根 README维护。本页不另建参数表。

候选入库：逐条决定

读取候选 → 检查冲突与版本 → 用户选择 → 单条执行 → 回读结果

候选情况用户可以选择执行边界
新增、删除、评分写入 / 丢弃 / 暂缓选择只授权当前这一条操作。
修改已有正文改写后写入 / 丢弃 / 暂缓先展示原正文与新正文，再确认。
目标记录已变更或删除丢弃 / 基于现状重新评估旧候选不能直接覆盖当前记录。
同一目标存在冲突核对证据后逐条决定不得把互相矛盾的候选直接合并入库。

中途中断时，已执行的变更保留，未处理候选留在暂存区。待处理候选不会因时间自动过期。清理会移除已处理与已失效条目，必须先核对范围。

概念与 scope

术语含义不要混淆
技能安装让宿主发现 Skill 指令与配套工具。不决定记忆存在哪个项目。
运行时部署向项目放入独立可运行的 psm-cli.js。不是整套 Skill 安装；普通使用不要求部署。
记忆库memory.md 保存正文与稳定编号。只暂存的候选还不是记忆记录。
暂存区cache.jsonl 保存待审核候选。自动保存表示暂存，不表示入库。该文件由 Git 忽略。
评分账本evidence.jsonl 保存评分与使用结果收据。不保存记忆正文或自由文本证据。
分类标准tags.json 定义标签规则与单条修正。标签是派生结果，不是记录的固定属性。
记录类型经验、避坑、决策、约束、事实。类型说明结论性质，不表示环境或访问权限。
记录状态active 参与普通读取；review 待复核；disabled 停用。待复核或停用不等于删除。

项目边界：选择哪一个库

数据目录固定为 <project-root>/.project-self-memory/。优先使用显式项目根，其次使用项目运行时绑定，最后使用启动目录。

工具不自动向父目录寻找项目。项目里指向全局运行时的链接，不等于项目独立副本。这是数据目录分隔，不是访问控制。

记录范围：标签不强制隔离

PSM 没有记录级 scope 固定属性。正文前缀 [env=prod] 可以派生 env:prod 标签，表达适用范围。

标签支持显式筛选，但不参与自动检索排序，也不强制排除范围外记录。使用前仍必须核对适用条件。

旧分组有 scope 描述文本，一条记录至多属于一个组。该文本不是权限规则。新分类推荐多标签，旧分组保持兼容，不自动迁移。

授权与安全

可以直接请求只读检查

  • 读取、目录、记录详情、证据查看。
  • 配置校验、库诊断、标签建议与统计。
  • 运行时状态、查看器只读浏览。

写操作必须明确范围

  • 候选入库、正文修订、合并、删除、评分。
  • 标签规则、旧分组、配置修复与迁移。
  • 项目运行时的部署或升级。
不得直接编辑活动文件。 让 Agent 调用 CLI，或在查看器中提交。不得保存凭据、个人数据、易失机器状态或未核验推断。

授权示例：「把记录 0001 改为刚才确认的新正文，现在执行。」只说「结论对」「继续讨论」「确认后保存」，不构成具体写入授权。

库结构未知或损坏时，停止写入并保留原文件。不得用初始化、重置或自动修复掩盖错误。已有具体授权且范围未变时，不重复确认。

常见问题

为什么记忆库没有本次的新结论？

先检查暂存区。自动收尾只暂存合格候选，不直接入库。读取、保存开关关闭或验证不足时，也不会生成候选。让 Agent 报告具体原因。

为什么没有加载某条记忆？

检查项目根、配置、记录状态和诊断。接入自动选择的宿主还会检查相关性、评分、新鲜度与上下文预算。显式读取与宿主自动选择不是同一行为。

找不到 CLI，是否把整个 Skill 装进项目？

不必。让 Agent 从本次加载的 Skill 基目录找发行运行时。已加载安装缺少产物时，报告安装不完整；不得切到另一版本掩盖错误。定位失败时，报告记忆未读取或未暂存，业务任务继续。

为什么保存显示冲突？

另一个写入方改变了记录或库版本。刷新并重读当前内容，比较差异，再决定重提。不得强制覆盖；失效候选必须重新评估。

为什么新正文不接受多行？

新正文必须紧凑单行，不以标题、列表或代码围栏开头。让 Agent 保留事实与字面量后改写。CLI 只校验，不改写语义。历史多行正文保持可读。

为什么修改正文后评分变了？

评分绑定记录版本。正文、类型、状态或旧分组变化时，版本变化；旧评分不自动继承。改标签分类标准不会改变记录版本。

为什么有标签，却仍读到其他范围？

标签是分类线索，不是 scope 强制隔离。自动选择不按标签排除其他记录。必须显式请求标签筛选，并现场核对适用条件。

为什么查看器打不开或只读？

浏览器未自动打开时，使用终端输出的完整带令牌地址。端口冲突时换端口。缺库或库损坏时只读诊断；不要因此直接编辑活动文件。

装好 Skill，就会自动运行吗？

安装只让宿主发现 Skill。提示词宿主由 Agent 按指令执行，不是后台守护服务。MemorySession 是可接入的自动流程入口，参考适配器不代表当前宿主已经接入。

文件能跨会话或跨项目共用吗？

记忆与暂存候选保存在项目中，可以跨会话读取；当前任务的读取态不长期保存。不同项目默认使用各自的数据目录，不自动共享全局记忆。团队分发取决于实际 Git 跟踪策略。

高级维护 按需展开

初始化与配置：先检查，再写入

仅在确认缺库或为空时初始化。init 创建缺失的数据配置与记忆文件，初始化账本，并补充暂存区的 Git 忽略规则；不部署可执行文件。

自动行为分别控制读取、候选暂存和评分候选。覆盖优先级为任务级、会话级、项目配置、默认值。会话级覆盖在本次任务收尾后或明确恢复时失效。

配置损坏时关闭自动行为。让 Agent 先校验，再展示修复计划；没有授权时不得重置。

请求：「检查本项目的 PSM 配置与库健康。先解释诊断，不重置、不修复。」

评分、版本与证据：先归因，再评价

record_id 是稳定编号。record_version 是记录内容与元数据的指纹。task_id 区分任务，event_id 区分证据收据。同一事件重试不重复计分。

有效性必须来自实际采用后的可观察结果。仅加载不算使用。环境故障、场景不匹配和原因不明不直接构成负面证据。

可信宿主的自动证据还必须匹配当前任务、已加载记录及版本。提示词宿主收尾只暂存新增结论，不自行生成评分候选。

请求：「检查记录 0001 的当前版本与证据。说明评分依据，先不调整。」

标签与旧分组：分类不等于适用性判断

标签来自正文前缀、关键词规则与单条修正。[host_scope=qbox,tgate] 派生两个标签。一条记录最多显示 8 个标签。

关键词规则使用不区分大小写的字面量子串。建议命令只统计前缀与重复词，不联网，也不自动采纳。标签损坏时关闭全部标签并给出 warning，普通记忆功能继续。

维护时先看建议与统计，再授权应用分类计划。查看器标签只读。旧分组保持兼容，分组变更会改变记录版本。

请求：「只读检查 PSM 标签覆盖率，提出分类建议。不要应用规则，也不要迁移旧分组。」

清理与合并：先核对候选，不做全库扫除

清理入口只讨论负分占优或达到既定负分条件的记录。具体条件见根 README。可以保留、修订、待复核、停用或删除。

合并必须保留较早的稳定编号，并核对新正文。盘点、评分、清理不代替暂存区审核；暂存候选单独走候选入库流程。

请求：「检查 PSM 的清理候选。按条说明保留或修改理由。不要删除或合并。」

查看器：人工浏览、编辑与审核

统一 preview 前台运行，只监听 127.0.0.1。默认打开浏览器；退出前台进程后，服务结束。

查看器支持标签筛选、正文/类型/状态编辑，以及暂存候选的查看、编辑并入、丢弃、清理。它不提供标签规则编辑。

写入前检查版本并创建备份。发生冲突时重读后再决定，不覆盖其他写入方的内容。不得把带令牌的启动地址发给他人。

这份离线手册只是文档，不是查看器，不会连接你的项目。

项目独立运行：只部署一个文件

普通使用直接运行已安装 Skill 的发行 CLI。仅在明确要求项目独立运行时，部署 .project-self-memory/psm-cli.js。项目运行时只依赖 Node 22+，不依赖相邻源码或第三方模块。

安装拒绝覆盖未知内容和符号链接。升级只替换能识别的官方旧产物，先备份再替换；不改记忆正文、评分、配置或暂存区。

运行时不联网自更新，不自动替换自身，也不替用户决定 Git 跟踪策略。文件哈希识别不是来源签名认证。

请求：「先检查本项目 PSM 运行时状态。说明是否需要独立副本，暂不安装或升级。」

旧数据与旧查看器：保留原件，显式迁移

self-memory/ 是只读旧数据来源。先扫描，再确认含快照与来源指纹的迁移计划。迁移可以部分成功；失败条目保留原字节。

当前存储格式是 v1。未知或未来格式拒绝迁移，不猜测修复。迁移的新正文也必须符合单行契约。

旧 view-memoery.js 保留，可以继续运行，但不自动获得新功能。旧查看器安装与更新命令拒绝执行；只读状态查询保留。新使用统一 preview。

请求：「只扫描旧记忆与旧查看器，给出迁移建议。保留原件，等待我确认。」

宿主接入与上下文预算：开发者参考

MemorySession 在任务开始时加载，在结束时暂存候选。自动选择先检查有效性与记录状态，再按相关性、可信度、新鲜度、旧分组多样性和 token 预算选择。

标签只提供命中观测，不加权排序。自动加载关闭时，不把记忆正文交给 Agent；配置或库校验失败时停止自动流程。

每个计量会话首次成功交付非空上下文时估算 token。严格超过 37,000 时发出提醒；任务继续。原始 CLI 读取不提供此会话提醒，提醒也不是清理授权。

实现细节见宿主适配器。本手册不声称当前生产宿主已经接入该接口。
