# 诊断输出脱敏规范

本规范适用于 probe 的标准输出、标准错误、临时文件、剪切板和用户回传后的二次检查。原则是保留诊断结构，最小化可识别性；无法可靠判断时优先遮蔽。

## 完全遮蔽

以下值替换为 `<REDACTED:CREDENTIAL>`，不要保留前缀、后缀或长度：

- Password、Token、Secret、API Key、Authorization、Cookie、Session ID；
- 私钥、助记词、数据库/云服务/Git/npm/Docker/CI 凭据；
- OAuth Client Secret、Bearer/Basic 凭据与连接串中身份验证部分。

匹配时应同时覆盖常见 `KEY=value`、`KEY: value`、HTTP header、URL query、JSON/YAML 键值和连接 URI 形态；只出现“token”字样但不含值的错误说明应保留。

## 部分掩码

| 类型 | 处理目标 | 示例 |
|---|---|---|
| 用户目录/用户名 | 保留结构，隐藏身份 | `C:\\Users\\alice\\app` → `C:\\Users\\<USER>\\app` |
| POSIX 主目录 | 保留结构，隐藏身份 | `/home/alice/app` → `/home/<USER>/app` |
| 主机名/邮箱/账户 ID | 用语义占位符替换 | `build-17` → `<HOST>` |
| IPv4/IPv6/MAC | 保留必要网段或类别 | `192.168.10.25` → `192.168.*.*` |
| 私有项目路径/组织名 | 保留模块层级，隐藏主体 | `D:\\customer-x\\api` → `D:\\<ORG>\\api` |

端口、错误码、软件版本、协议、权限位、配置键名、时间戳、已脱敏路径结构和退出码通常保留，因为它们是诊断证据。

## 安全执行顺序

1. 采集内容仅存在于进程内存或受控流中；不得先打印原文再处理。
2. 先完全遮蔽凭据，再部分掩码身份与位置，最后检查是否残留疑似敏感内容。
3. `redaction_status=ok` 才能自动写剪切板；`review` 或 `failed` 时禁止写入，保留终端人工审查路径。
4. 临时文件只能保存已经脱敏的报告，随机命名且拒绝覆盖。
5. Agent 收到用户粘贴内容后再次检查；若发现凭据，不引用其值，不写入长期记忆/Issue，并提示用户轮换。

## 允许的例外

用户可明确要求保留某个非凭据标识用于本次私有诊断；仍应先说明暴露风险。任何明确授权都不能允许回显密码、Token、私钥、Cookie 或认证头。
