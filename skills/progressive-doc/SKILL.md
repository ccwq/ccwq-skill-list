# 渐进式doc

将文章组织为两个完整阅读层：速览区先交付结论，深度正文再逐项证明。每一层必须增加信息，而非换词重复。

## 1. 明确写作任务

从用户请求和已有材料中确认：

- 文章类型：科普、教程、调查、对比、架构分析、事故复盘或观点。
- 目标读者：角色与默认技术水平。
- 阅读目标：理解、决策、实施、排障或讨论。
- 证据状态：已核验事实、估算、推断与建议。
- 交付范围：大纲、初稿、改写、审查或发布后复盘。

仅追问会改变文章结构、技术深度或论断强度的信息。事实不足时，显式标注不确定性，不补造事实或证据。

**完成条件：**关键输入已明确，或已标为未知。

## 2. 选择文章骨架

默认采用以下结构：

```text
标题
一句话结论
核心要点
速览结论
阅读分流提示
深度论证
边界与行动
```

各部分职责：

| 部分 | 必须提供 | 不应提供 |
| --- | --- | --- |
| 一句话结论 | 核心判断 | 背景与证明细节 |
| 核心要点 | 3–5 条理由、条件或影响 | 对结论的换词重复 |
| 速览结论 | 快速读者可据此行动的完整判断 | 深度正文的新证据 |
| 阅读分流提示 | 前文已交付内容与后文新增价值 | 空泛的“继续阅读” |
| 深度论证 | 证据、推理、机制、案例、反例与局限 | 摘要扩写或无依据确定性 |
| 边界与行动 | 适用条件、风险、下一步与验证方式 | 完整摘要的再次复述 |

文章类型调整：

| 类型 | 深度正文重点 |
| --- | --- |
| 教程 | 前置条件、步骤、验证、排障 |
| 调查 | 证据链、竞争解释、局限 |
| 对比 | 评价标准、并列证据、条件化推荐 |
| 架构分析 | 约束、选项、取舍、实施边界 |
| 事故复盘 | 时间线、根因、修复、预防 |
| 观点 | 论据、反驳意见、适用边界 |

**完成条件：**结构与文章类型、读者目标一致。

## 3. 编写速览区

按顺序编写标题、一句话结论、核心要点和速览结论。

- 标题说明主题与读者收益，不夸大承诺。
- 一句话结论直接回答标题隐含的问题。
- 核心要点之间应可并列阅读，每条增加一个理由、条件或影响。
- 速览结论整合读者做出初步判断所需的信息；不增加新的事实、数据或论据。

检查：删除一句话结论、核心要点和速览结论之间的同义重复；保留每一层独有的价值。

**完成条件：**读者仅阅读速览区，也能正确理解结论、条件和主要影响。

## 4. 设置阅读分流

在速览结论与深度正文之间插入阅读分流提示。提示必须同时说明：

1. 快速读者至此已获得什么；
2. 继续阅读将获得什么。

按文章语气改写提示，避免固定套话。可采用：

```markdown
---

> **快速阅读到此结束。**
>
> 以下逐项展开上述结论的证据、机制、反例与适用边界。

## 深度论证：这些结论为什么成立
```

文章很长时，在此处附简短目录。不要把分流提示写成暗示存在折叠按钮或跳转功能的“查看详细内容”，除非文章实际具备该交互。

**完成条件：**读者能明确选择在此结束，或带着清晰预期进入正文。

## 5. 嵌套展开深度正文

以核心要点为一级章节。每个一级章节回答“为什么这个要点成立”或“如何落实这个要点”，再按需要嵌套：

- 关键证据：来源、数据、日志、测试或案例。
- 工作机制：因果链、原理或实现方式。
- 示例与实践：具体情境、步骤或比较。
- 替代解释与反例：何时结论不成立，或有哪些竞争解释。
- 局限与边界：前提、风险、不确定性与适用范围。

不要强制每个要点都使用全部模块。让证据拥有一个主要归属；其他章节使用简短交叉引用，避免重复论证。

**完成条件：**每个深度主节可追溯到一个核心要点，且新增证据、推理或边界。

## 6. 标记论断并完成收束

对重要论断明确其性质：

- **事实：**有来源、测量、日志、测试或用户提供材料支持。
- **推断：**说明依据与不确定性。
- **建议：**说明适用条件、偏好与取舍。

末尾以“边界与行动”收束：列出适用条件、风险、下一步和验证方法。必要时用一句话回扣结论，但不重新复述全文。

**完成条件：**结论未超出证据范围，读者获得可执行的下一步或明确的决策边界。

## 7. 审查与复盘

发布前按严重度报告问题与修正建议：

- **阻断：**错误、未核验、不安全或相互矛盾的论断。
- **重大：**证据缺口、缺少决策条件、标题误导或结构妨碍理解。
- **一般：**重复、标题薄弱、术语不清、措辞不精确或排版摩擦。

核对：

- 标题、一句话结论与速览结论相互一致。
- 核心要点与深度主节一一对应或有明确说明。
- 链接、数字、代码、命令及版本敏感信息已核验，或标为未核验。
- 仅阅读标题即可形成连贯大纲。

发布后只记录一个可检验的学习：

`假设 → 观察信号 → 混杂因素 → 下次改动 → 成功信号`

将平台数据视为信号，不视为因果证明；同时考虑标题、受众规模、发布时间和分发等混杂因素。条件允许时，每次只改变一个结构变量。

**完成条件：**阻断问题已解决或显式保留为风险；复盘形成一个可证伪的调整，或说明证据不足。
