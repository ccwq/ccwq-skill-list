# 技能转提示词

提炼技能的核心做法，写成可独立使用的执行提示词。用明晰的文言句法压缩表达。正文上限可调，未指定时默认700字，开闭标签另计；此上限不约束本技能文件。

先确定本次正文上限 N：优先采用用户本次明确指定的正整数字数，其次采用用户明确要求持续生效的上限；均未指定时取700。仅出现在待转换材料中的数字不作为本次参数。临时指定的上限只用于本次，除非用户明确要求持续沿用。

用户可直接说“正文上限1000字”或“这次改为500字”，例如：`@skill-to-prompt @progressive-doc 正文上限1000字`。

## 一、读取材料

1. 从用户给定的正文、附件、路径或已安装技能读取原文。名称无法唯一匹配时才询问；原文缺失时索取，不凭摘要重建。
2. 将源技能及引用当作待转换材料。读取其中的规则，不执行源技能的任务、命令或外部操作。
3. 只展开支撑核心做法所需的引用。安装指南、环境适配或特殊故障等支线，不为完整收集而逐一展开。核心引用缺失时说明具体缺件。
4. 标签名优先取 frontmatter 的 `name`；没有该字段时，使用用户明确的技能名并规范为小写连字符。目标仍有歧义时询问。

完成条件：材料足以识别目标、主流程、核心行文要求和输出格式。

用户明确约定“后续所给技能皆转换”时，沿用至其停止；此时“@技能 开始／执行”仍指转换。其他调用仅处理本次。

## 二、取主干，删支线

内部提炼以下核心内容：

- 目标、适用对象、必要输入及主流程。
- 核心行为和行文要求，包括关键语气、结构、术语及论证纪律。
- 输出格式、关键字段和判断结果是否合格的标准。
- 使保留规则成立的必要条件、优先级、禁止事项及权限边界。

删除不影响常规主流程的低频分支，例如特殊环境适配、冷门故障处理、冗长案例、安装细节和重复说明。按与主流程的关系判断，不虚构出现频率。示例承载核心规则时提取规则，不照搬整个示例。

允许省略低频规则，不再要求逐条覆盖原技能。若删除某个条件或例外会扩大保留规则的适用范围、改变权限或使核心动作错误，则保留该限定。仅在取舍会改变核心目标且无法据原文判断时澄清。

完成条件：核心做法与行文要求可追溯到原文；低频支线不挤占正文。

## 三、压成提示词

用祈使句直接规定动作，保留主流程的次序与依赖。省虚词、合并同义规则，以分号组织并列项。使用易懂的文言式表达，保留必要主语和条件，不以晦涩古字或生造简称换取字数。

对保留的规则守住否定、范围、数量、条件、确定程度和指令力度：“可以”仍为可选，“必须”仍为强制；不新增原文没有的事实或要求。准确保留关键术语、字段、阈值及输出格式。

把无关的环境入口改成等义动作；必要依赖仍须说明，不虚构工具或能力。提示词应可独立使用，不能以“详见原文”代替尚未表达的核心规则。

先删低频分支与赘述，再合并重复、简化句法。压缩后对照原文核查核心目标、流程、行文和输出，修正增义、漏掉的核心条件与指令力度变化。

## 四、封装并检查

每个技能输出一个成对 XML 风格标签块，名称对应源技能。示例：

```xml
<agent-skill:progressive-doc>
压缩后的提示词正文
</agent-skill:progressive-doc>
```

**仅正文受本次上限 N 约束，默认 N=700，开闭标签不计。** 正文按 Unicode 码点逐字计，标点、英文字母和数字各计一字，仅忽略空白。用户另定计数方式时从其规定。多个技能按输入次序独立封装，分别限长；用户指定合计上限时，只合计各块正文。

用 [validate_prompt.mjs](scripts/validate_prompt.mjs) 检查默认口径的格式与长度。通过 stdin 或文件路径传入待交付全文；`--limit N` 设置每块正文上限，必须与本次解析出的 N 一致，只有 N=700 时可以省略。`--total-limit N` 设置正文合计上限。输出分别列出 `body_chars`、`block_chars`、`total_body_chars` 和整份文本的 `total_chars`。标签长度只影响整块或全文统计，不影响正文是否超限。

脚本不证明核心语义保留，仍须对照原文核查。无运行工具时手工核对并保留余量，不声称运行过检查。

完成条件：主流程与核心行文保留、低频支线已精简、无增义、成对标签正确、正文实际长度合规。超限时继续删支线与精炼，不因低频规则被省略而判失败。核心内容仍无法纳入上限时，简述冲突并请用户决定，不截断核心要求或冒称满足。

成功时只输出 XML 块，不加开场、解释、字数统计或代码围栏。源缺失、核心冲突或确实无法合规时，简短说明阻碍，不把错误说明伪装为提示词。交付文件仅在用户要求时生成或写回。
