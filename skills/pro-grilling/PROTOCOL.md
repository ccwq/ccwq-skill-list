# Pro Grilling 协议

## 使命

通过高信息增益的单问题循环，沿决策树厘清真实目标、关键约束、核心取舍、依赖、风险、验证方式和行动边界。新情报必须能够改变后续问题、轮次或分支；不得把流程执行成固定问卷。

## 一、初始化

1. 识别当前事项和用户已提供的信息，不重复询问已有答案。
2. 判断复杂度、主要信息缺口和潜在风险，预估总轮次；总数允许动态调整。
3. 开场说明复杂度、主要缺口和预计轮次。
4. 若事项缺失，只询问“当前要讨论的事项是什么？”，收到回答后重新初始化。
5. 若开始前的调查可能实质改变判断、问题顺序或路径，先询问调查档位；否则直接进入提问循环。

初始化完成条件：当前事项明确，复杂度与主要缺口已判断，预计轮次已给出，必要的调查档位已由用户选择。

## 二、调查分级

调查档位只有三种：

- 直接继续：不新增调查，依据现有信息推进并标记不确定性。
- 快速核验：只核验最可能改变当前判断的关键事实。
- 充分调查：系统核查主要事实、替代路径、风险和冲突证据。

低成本、只读、稳定且可快速确认的事实可以自行查证，不应转化为用户问题。

当调查可能显著改变结论、分支或问题顺序时，必须说明：

1. 当前缺失的关键事实；
2. 调查可能带来的具体收益；
3. 推荐档位及理由；
4. 时间、范围或不确定性的主要代价。

用户对某一阶段作出调查授权后，可在该阶段范围内连续进行低风险只读调查。若对象、范围、成本、风险或任务路径明显变化，必须重新请求授权。

调查完成条件：已获得所选档位要求的证据，已记录来源、冲突和不确定性，并据此更新决策树、预计轮次与下一问题。

## 三、单问题循环

每轮只提出一个问题，并等待用户回答后再继续。

每次提问前标注“第 n/[total] 问”。总轮次变化时，从下一问开始使用新总数，并用一句话说明调整原因。

问题选择顺序：

1. 优先选择最可能改变最终结论或后续路径的问题；
2. 优先处理目标、偏好、优先级、风险承受和关键取舍；
3. 不询问可通过文件、工具、环境或可靠资料自行确认的事实；
4. 不为覆盖固定层级而提出低收益问题；
5. 每次回答后重新评估目标、现状、障碍、根因、假设、矛盾、取舍、验证和边界，只选择当前必要层级。

每个问题必须包含：

- 可选答案或回答方向；
- 建议答案；
- 简短推荐理由；
- 主要代价或局限；
- 重大决策可补充后续影响。

本轮完成条件：用户的答案已被准确复述为决策或约束，决策树已更新，下一轮只保留当前信息增益最高的问题。

## 四、分支调查中断

在第 n 问之后出现新的逻辑分支，且调查后继续能显著提高收益时：

1. 暂停原定下一问；
2. 用精炼文字说明新增事实缺口和调查价值；
3. 询问用户选择直接继续、快速核验或充分调查；
4. 调查后重排后续问题，而不是回到原有脚本。

不得因为普通不确定性反复请求调查。仅当新证据显示原结论可能明显失真、风险上升或当前分支无法继续时，才能重新触发已被拒绝的调查。

分支调查完成条件：调查结果已进入当前状态，原假设已复核，问题顺序和预计轮次已按结果更新。

## 五、分阶段执行

纯分析上的步骤拆分可以自动进行，无需征求用户同意。

若后续判断依赖中间操作结果，先说明：

1. 为什么需要拆分；
2. 分阶段能避免的主要错误；
3. 增加的交互、成本或时间；
4. 推荐是否采用“执行一步—核验结果—再决定下一步”。

随后只询问用户是否采用分阶段模式。

用户同意分阶段推进，不等于授权所有具体操作。涉及写入、费用、隐私、外部沟通、高风险或不可逆影响的步骤，必须分别获得明确授权。

每个阶段只执行已授权范围内的最小必要操作，完成后必须：

- 汇报执行内容；
- 给出证据或变更清单；
- 验证结果；
- 说明新情报如何改变下一步；
- 再决定后续问题或操作。

阶段完成条件：本阶段结果已验证，新增情报已写入决策状态，下一阶段是否存在及其授权边界已明确。

## 六、子智能体

先判断当前环境是否支持子智能体。不支持时由主智能体完成，不向用户询问可自行探测的能力事实。

支持时，仅在以下收益明确的情况下使用：

- 可独立并行的调查或比较；
- 独立复核、交叉验证或测试；
- 多文件、批量或边界清晰的执行；
- 复杂子任务会显著污染主上下文。

主智能体始终负责用户沟通、授权管理、决策树、任务边界、结果验收和冲突裁决。

子智能体只能继承用户已授予且主智能体明确下放的权限，不得扩大对象、范围、风险等级或继续转授权。遇到范围外操作、新增风险、重大冲突或权限不足时，必须停止并回报。

子智能体回传必须包含：

- 子任务边界；
- 使用的证据；
- 执行或分析结果；
- 验证结果；
- 变更清单；
- 冲突与遗留问题。

子任务完成条件：回传信息足以让主智能体独立验收，且没有未披露的权限扩张或未验证结果。

## 七、拒绝与降级

用户拒绝调查或分阶段执行后：

1. 基于现有信息继续；
2. 记录被拒绝事项及其造成的不确定性；
3. 不立即重复请求；
4. 在结论中保持对应置信度；
5. 只有出现新的实质理由时才能再次询问。

若缺失信息使可靠判断无法成立，暂停该分支，明确说明无法成立的原因，不得伪造确定性结论。

降级完成条件：用户选择得到尊重，不确定性已可见，后续问题仍能在现有证据下产生实际信息收益。

## 八、回退与重构

若发现前提错误、目标模糊、问题定义不成立、关键假设被推翻或分支失去意义：

1. 立即暂停当前分支；
2. 指明被推翻的前提及证据；
3. 回退到最近仍成立的决策节点；
4. 更新预计轮次；
5. 只提出重构后信息增益最高的一个问题。

回退完成条件：新的问题定义与现有证据一致，失效分支不再影响后续判断。

## 九、收敛检查

当以下内容均已明确时，停止扩展新问题：

- 真实目标与成功标准；
- 关键约束与行动边界；
- 核心取舍及主要依赖；
- 主要风险与验证方式；
- 仍未解决但可能影响结果的问题。

先输出阶段总结：

1. 当前共识；
2. 已确认的关键决策；
3. 主要依赖与风险；
4. 验收标准；
5. 剩余未决项。

若未决项不会实质影响结果，建议结束提问并请求用户确认“ok”。若仍会影响结果，只继续询问影响最大的一个问题。

在用户明确确认“ok”前：

- 不执行实际操作；
- 不直接产出最终方案；
- 可以进行分析、只读查证、比较和共识总结；
- 不把调查授权解释为写入授权。

本技能完成条件：收敛检查通过，阶段总结已输出，用户明确确认“ok”。确认后仅结束 grilling；后续方案或执行仍以用户的明确请求和授权为准。
