# 内置 STE 表达规则

本文件独立包含表达约束，不调用外部 STE 技能。依据 ASD-STE100 原则写简明中文；不得冒称标准原文。不使用文言文。更高优先级指令及用户指定格式、语言优先。

## 范围与结构

只约束 reptlite 简报、调度反馈及相关决定请求。普通任务回复、代码、注释、提交信息、写入项目的文件及原样引用不受本文件风格约束。引用内容保持原样。

先写关键信息。汇报工作时先写状态及明确范围，再给证据。进度先写当前动作与对象；决定请求先写待决事项；普通解释不强套模板。每段一个主题，不超过六句。不叙述操作过程，不重复旧文字制造进展。

## 用词与句长

- 一词一义，同一概念只用一个名称。专用词先定义；只有一两个时在首次出现处括注。
- 使用具体动词和主动语态。主语有歧义时补全；执行者未知或无关时可以被动表达。
- 一句一事；条件在前，动作在后；不得双重否定。名词串不超过三个名词。
- 中文步骤句不超过 30 字，描述句不超过 40 字。汉字、英文词、数字、标识各计一，标点不计。英文步骤不超过 20 词，描述不超过 25 词。
- 情态词只用「必须」「不得」「可以」，分别表示强制、禁止、准许。
- 界面名称、标识、命令、路径、版本及错误串保持原文；代码标识、命令和路径使用反引号。
- 步骤使用编号及祈使句，一步一个动作。三个以上并列项使用列表。不得以「等」「之类」隐藏未列项。

## 状态与证据

工作状态只用以下固定词，并注明对应范围：

| 状态 | 使用条件 |
|---|---|
| 已完成 | 所述动作全部执行完毕；不自动表示效果已验证 |
| 部分完成 | 列出已完成、未执行和失败的部分 |
| 未开始 | 尚未执行动作 |
| 进行中 | 动作已开始且尚未结束 |
| 已验证 | 检查已执行且通过；写方法、结果及范围 |
| 未验证 | 已知检查未执行；写原因 |
| 失败 | 动作或检查未达到要求；引用关键失败输出 |
| 跳过 | 有意不执行；写原因 |
| 阻塞 | 缺少条件无法继续；写缺少的条件 |
| 未确认 | 证据不足；写确认方法 |

工作与验证分开。必需检查未执行或失败时，不称整项完成。未执行检查用「未验证」；是否执行或结果不明用「未确认」。不得把资料结论冒充运行验证。实际效果结论必须包含验证状态、方法、结果及范围；同一证据集中写一次。

「疑似停滞」只作为诊断提示，放入阻滞栏，不作为固定状态词。调度开关使用配置字段「启用：是/否/未确认」，不要把开关值混作工作状态。

证据必须可定位：文件使用路径与行号；工具结果使用任务标识、时间戳或运行记录；命令保留完整内容。证据不足时注明缺项与确认方式。不得编造事实、百分比、时间、产出、工具返回或恢复成功。

请求决定时使用编号选项，每项写动作及后果；推荐项居首并标「推荐」。没有决定需求时不强加确认流程。

发送前核对：核心信息在前、范围明确、固定状态正确、工作与验证分开、证据可定位、句长符合要求、无虚构事实、无无效重复。
