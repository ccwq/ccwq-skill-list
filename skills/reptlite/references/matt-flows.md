# Matt 流程适配

## 何时适用

当前任务确实在执行 implement、implement-spec 或 wayfinder 之一时。

三个条件分别确认，逐一判断：

1. 技能定义存在且可读。
2. 宿主允许模型调用该技能。宿主限制手动调用时，不绕过限制，也不把读取定义当作调用成功。
3. 当前任务正在使用该流程。技能定义存在不等于正在执行该流程；对话里出现技能名不构成适配依据。

技能定义不存在时，跳过本文件，用普通简报。当前任务使用该流程但技能定义不可读时，说明这一限制，不推测其内容。

任务记录是否可读不作为适配前提。记录不可读时按「缺失与降级」处理，说明缺什么，不静默回退普通简报。

## ask-matt 的定位

ask-matt 是流程导航，说明技能之间的关系。它不提供任务状态、耗时或剩余范围，不作进度来源使用。

需要确认流程关系时读取它的定义。宿主限制手动调用时，不绕过限制，也不把「读取定义」写成「调用成功」。

## 摘要来源

| 流程 | 摘要来源 |
|---|---|
| implement | 当前工单及其执行、验证记录 |
| implement-spec | 当前 spec、关联工单及依赖记录 |
| wayfinder | 当前 map 与决策工单 |

工单、spec 和 map 的存放位置按当前项目的 issue tracker 配置确定，不套用其他仓库的布局。

## 摘要写法

在 Agent 表之前加两行：

> 已完成：#01 接口实现；#02 单元测试。
> 待执行：#03 集成验证。

- 事项多时给关键项与数量，并指向完整清单，不逐条复述工单正文。
- 进行中和阻塞事项放在对应摘要行，附状态。
- 证据通过工单引用定位。

## 语义区分

- 工单的 triage 状态不等于实施完成。
- wayfinder 的决策解决不等于代码交付。
- 工作完成不等于验证通过。

## 缺失与降级

- 相关技能不存在时，跳过对应适配，保留普通任务简报。
- 任务记录缺失或互相冲突时，说明缺什么，并说明它影响哪段摘要。不编造清单，不自行创建或修改工单。
- 只读取和汇报任务记录。不因此启动新的工程流程。
