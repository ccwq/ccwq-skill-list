# reptlite — report-lite

## 用法

把 `/reptlite` 视为用户调用语法。宿主支持 `$reptlite` 或 `@reptlite` 时，按宿主入口加载同一技能；不得谎称已经注册可执行 CLI 命令。

调用示例与参数速查统一维护在仓库根 [README.md 的 reptlite 小节](../../README.md#reptlite)。以下执行入口保留独立安装所需的参数语义，首次启用时附简短用法。

周期 N 接受有限正数，包括小数，单位为分钟。缺值、零、负数、非数字、未知参数或多个动作混用时，显示对应用法，保持现有调度不变。宿主不支持该精度时，说明请求周期、支持精度和可用值；不得静默取整或擅改周期。

使用本包 agents/openai.yaml 的 policy.allow_implicit_invocation: false 保持仅显式调用。迁移到其他 Agent 时，使用其等效的手动调用设置；Claude Code 使用 disable-model-invocation: true。无法强制手动调用时说明限制，仍不得因任务特征自行启用。

只对本次显式调用负责。用户引用、讨论、编辑本技能或查看示例，不代表启用。自动回调仅执行已授权简报，不重新启用技能或创建新调度。

## 执行入口

1. 解析参数，识别当前任务、会话和现有 reptlite 调度。没有可识别任务时，说明缺少报告对象，不创建空转调度。
2. 所有面向用户的简报和命令反馈，先读并执行 [内置 STE 表达规则](references/ste.md)。这些规则只约束本技能输出，不改变普通任务回复的风格。
3. 无参数、`--reset-interval/-r`、`--kill/-k` 或 `--status/s`：读 [调度适配](references/scheduling.md)，仅使用匹配宿主的分支。`--immediate/-i` 只立即报告一次，不改变周期调度，也不依赖调度器。
4. 无参数：为当前任务启用默认每 2 分钟的周期简报。探测真实可用工具，复用同任务现有调度，避免重复。创建后回读调度标识、实际周期、目标会话和启用状态。核对成功才报告调度配置「已验证」；首次投递仍为「未验证」。
5. `-r N`：仅修改已存在的本技能调度，周期为 N 分钟，从修改时重新计时。停止状态下只保存配置，不擅自启用。修改后核对周期和下次时间。宿主只有删除再建时，先验证参数；记录旧配置，明确任何失败后的实际状态，不声称成功回滚。
6. `-k`：仅停止本技能的周期调度，保留主任务和所有子 Agent。按已记录的所属标识取消或暂停本技能调度，并回读确认。查不到所属标识时先定位，无法定位则写「未确认」，不得删除其他任务。重复停止保持幂等。
7. `s`：报告开关、宿主及后端、请求与实际周期、所属调度标识、最近实际简报时间、下次触发时间及投递验证状态。未知值注明「未确认」及确认方法；没有调度时写明未启用，不创建调度。
8. 每次回调前确认开关、所属任务和会话。开关关闭时跳过。任务结束时给最终简报并撤销所属调度；撤销失败则报告残留标识和影响。

把以下状态保存在宿主支持的会话元数据中：任务/会话标识、开关、后端、所属调度标识、请求与实际周期、最近实际简报时间、下次触发时间、各 Agent 最近进展/回应时间和催办记录。需要跨回合恢复而宿主无元数据时，使用该任务允许写入的持久位置，并保留时间戳及所属关系。不得把技能安装目录作为运行状态存储。状态无法持久保存时说明恢复限制。

## 简报

先用一行说明任务目标，再用一行说明总体进度。随后固定使用 Markdown 表，逐一列出主 Agent 和本任务中所有已启动子 Agent；每个 Agent 单独一行，保留已完成者至任务结束：

| Agent | 状态 | 实绩与产出 | 阻滞 |
|---|---|---|---|
| 主 Agent：名称及职责 | 进行中 | 本周期实际产出；证据位置 | 无 / 具体缺项 |
| 子 Agent：名称及职责 | 未确认 | 尚无可核对产出 | 最近回应时间未知；查询状态 |

按真实证据替换示例。状态只用内置 STE 规则中的固定词。无新进展时直写，并给已知原因；原因未知写「未确认」。不用主观百分比。完成的工作与验证结论分开；验证说明方法、结果和范围。普通进度不强加验证模板。

没有子 Agent 时只列主 Agent，不创建子 Agent。默认每格一句短语；只有异常时补充影响和下一步。用户索取细节时再展开，避免周期报告膨胀。

## 子 Agent 检查与催办

- 每次实际报告时，查询本任务各子 Agent 的状态、可观察产出和最近有效回应。仅有「已启动」「进程存在」或「没有报错」不足以证明进展正常。
- 连续两个实际检查周期内，既无实质进展，也无有效回应时，记录「疑似停滞」为诊断提示，放入阻滞栏。工作状态证据不足时用「未确认」；已知缺条件导致无法继续时用「阻塞」。有效回应必须包含当前阶段、产出或具体等待条件，机械复读不算。
- 调度延迟、漏触发或主 Agent 忙碌不能证明子 Agent 停滞。没有检查覆盖时写「监控中断；状态未确认」，恢复后先查询，不把漏过的触发次数当作检查次数。
- 发现疑似停滞时，先检查，再用宿主的子 Agent 通信接口催办，索取当前状态、已完成事项和阻塞原因。仅限本任务已启动的子 Agent，不扩展为外部消息发送。
- 下一次实际检查仍无有效回应或进展时，报告已知原因、影响及建议；未知原因写「未确认」。明确失败或明确阻塞即时报告，不等待下一周期。
- 监控无查询或通信接口时，分别声明限制。不得把催办请求已发送写成恢复成功；不得擅自终止、替换或改派子 Agent。主任务继续推进不依赖该子任务的工作。

## 调度回调内容

创建调度时，把本节所需的完整规则作为普通文本回调指令，或引用已验证在回调环境可读的绝对路径。不得只写 `/reptlite -i`：显式调用专用技能在部分宿主不能由定时器再次加载。

回调至少绑定：所属任务/会话和调度标识、开关与完成检查、目标与总体进度、固定四列表、内置 STE 规则、逐个子 Agent 查询与停滞催办规则、结束后的所属调度清理。若回调环境无法读取引用内容，内联这些规则。回调只报告和检查，不递归建任务。

## 完成与限制

区分：调度已保存、调度已启用、触发实际发生、简报成功投递。每项单独依据工具返回核对。无首次投递证据时，不宣称端到端验证通过。

没有可用后端、请求周期不受支持、缺权限、创建失败或无法投递时，明确说明原因与影响，保留 `-i` 手动能力。不得用口头承诺或阻塞式 sleep 循环冒充定时任务。仅在后端确认后启用周期简报。

定时器不是独立故障看门狗。主 Agent 忙碌或卡死时，同会话定时器可能无法报告；告知实际调度边界，不承诺严格准点或必能发现挂起。
