# 历史教训与流程背景

来自 2026-11-04 首次全量生成会话（session `32449e72`）与 2026-11-17 skill 固化会话的实测教训。转换前必读。

## 全量流程的由来

首次生成时的仓库形态：33 项正式 Skill。当时验证有效的做法，已固化为 SKILL.md 的六步流程。以下教训是流程各步骤的依据。

## 盘点教训

- 仓库内同一 SKILL.md 可能存在多份副本：历史工作树 66 份、暂存 1 份、评估快照 1 份、安装验证 2 份。盘点必须只认 `skills/*/SKILL.md`，并与 README、marketplace 名称集合交叉核对。
- `marketplace.json` 可能存在旧路径遗留与失效的 `pluginRoot`；适合交叉核对名称，不适合直接当取源路径清单。
- `plugin.json` 只列主分组，不能据此认定仓库全部 Skill 数量。

## 筛选教训

- 收录判据是「保真使用」，不是「有提示词价值」：转换后仍需联网、文件操作或终端验证的，归工具型而非普通聊天；删掉工具依赖后只剩泛化建议的，说明转换会改变用途，应排除。
- 诊断类三项（`agent-human-debug`、`joint-debugging`、`network-debug`）的收录靠「用户执行命令＋回传结果」模式成立；这是用户显式确认的边界，不是默认推断。
- 边界项逐条问一个实质问题即可，不长问卷。当时确认的问题：「是否允许普通聊天 AI 给出命令，由用户执行并回传？」

## 转换教训

- 四组并发分片（写作 / 教学决策 / 人机诊断 / 交接）各写各的 parts 文件，主代理独占根文档与 `.env`，当时无写冲突。
- 720 字边界实况：`agent-human-debug`、`joint-debugging`、`handoff-portable` 恰为 720 字。编辑这三项时几乎没有余量，任何增补都必须等量删减，或申请提高上限。
- 源 Skill 依赖过程文件（地图、工单、票）时，按 skill-to-prompt 的文件存储分支改写为会话内过程文件约定（四个双引号格式），如 `wayfinder`、`writing-for-agents` 的条目。
- 附加要求用 `.env` 的 `SKILL_TO_PROMPT_ADDON__<名>` 传递（如 `reptlite` 的参数简化与 `:rp` 快捷参数），转换前必读，转换后保留。

## 校验教训

- `validate_prompt.mjs` 拒绝标签块外的一切文本，不能把整份 Markdown 直接喂给它。必须先提取标签块再通过 stdin 传入。新版校验器已内置此提取。
- `.env` 清单值含反斜杠续行。解析时先全文合并续行（`replace(/\\\r?\n/g, '')`）再按行匹配，否则只取到行尾，清单被截断。
- 机械校验通过不证明语义保真，两者是独立关卡。

## 语义复核教训

首次全量的独立复核抓出 4 处机械校验不可能发现的问题：

1. `skill-to-prompt` 自转换时，正文嵌入了字面的 `<agent-skill:...>`，触发嵌套标签判定。
2. `wechat-headlines` 标题长度规则的读取/预测边界被压缩失真。
3. `engineering-method-selector` 的方法卡边界（哪些方法必须展开）与源文不一致。
4. `tutor-man` 的事实核验触发条件被弱化。

复核要逐项核对：目标、次序、必要条件、禁止事项、数量阈值、授权强度、输出字段。

## 第三方教训

- 前置材料缺失时不交付标签块（`infocard-q-style` 缺生成指南与 HTML 骨架，列 PENDING），不自行补造模板。
- 包内声明「license: MIT」但未附完整许可文本的，来源说明写「完整许可未随包提供」，不推测。
- ZIP 取材记 SHA-256，声明它是本地文件标识，不是上游发布签名。
- 未知许可不等于获得开源许可；仓库根 MIT 不自动覆盖第三方原始材料。
